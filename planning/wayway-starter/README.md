# WayWay starter kit

Starting files for Milestone 3. The JSON contract is the reference for the whole team.

| File | What it is |
|---|---|
| `contract/contract.ts` | JSON contract: data shapes shared by frontend, AI, logic and evaluation |
| `contract/example_response.json` | Example response of `POST /api/chat` (round 2, options A and B) |
| `contract/example_private_response.json` | Example response of `POST /api/private` |
| `metrics.py` | Logic and metrics: satisfaction levels, Gini, maximin, fairness credits, safety checks |
| `spots_tokyo.json` | Start of the curated Tokyo spots dataset (to extend to 30-50 spots) |
| `scenarios/` | Test scenarios with simulated personas (scenario 2 done; write 1 and 3) |
| `run_scenario.py` | Runs a scenario against the app with LLM-simulated personas |
| `.env.example` | Required environment variables (never commit real keys) |

## Team decisions
- **Satisfaction scale**: 5 fixed levels, the same for AI estimates and human votes:
  `must_go` (10), `want_to_go` (7.5), `same` (5), `lean_not_go` (2.5), `definitely_no` (0).
  Numbers are used only by code. "Satisfied" = `same` or better.
- **Rounds**: at most 3 refinement rounds, then a final group vote.
- **Round timeout**: the next round starts after 30 min, even if someone has not answered.
- **IDs**: unique ids (uuid) generated by Supabase.
- **Final vote**: valid only with at least 60% of the group, rounded up (4 members = 3 votes). Without quorum, voting is extended by 30 min. Non-voters are not counted.
- **Ties**: a perfect tie triggers one revote; a second tie gives the win to the candidate option.
- **"Definitely no"**: at most 2 per member per day.
- **Group split**: applied only if every member placed in a branch accepts (`acceptsSplit`); otherwise the best non-split option wins.
- **Fairness credits** (hidden from users, earned only at the final decision):
  - after each decision, a member earns as many credits as levels lost between their favorite option and the chosen one (max 3 per decision);
  - each credit adds +0.1 to the weight of their preferences in the "best for the group" total (max weight 1.5);
  - when their favorite option is chosen, their credits reset to 0;
  - WayWay never shows numbers, only a sentence: "Mia's choice is favored a little this time: she compromised at lunch."

## Coordination protocol (from Papachristou et al.)
1. WayWay posts 2-3 options in the group chat (`OptionSet`, round 1, status `collecting_feedback`).
2. Each member reacts privately to WayWay (`POST /api/private`); WayWay extracts preference statements.
3. WayWay refines the options (`nextRound: true`): it keeps the decision candidate and proposes options that satisfy at least as many members.
4. After at most 3 rounds (status `voting`), members vote; WayWay records the `Decision`, updates fairness credits and the itinerary.

## Who computes what
- **LLM**: extract preferences, propose options from allowed spots, estimate each member's level, write messages.
- **Code**: filter hard constraints, compute metrics, pick A (best weighted total) and B (fairest), fairness credits.

## Try the logic
```bash
python3 metrics.py
```

## Run a scenario (once the app's API exists)
```bash
pip install anthropic requests
cp .env.example .env   # fill in your key
python3 run_scenario.py scenarios/scenario2_conflict.json
```
The scenario's trip and members must be created in the app first, with the ids written in the scenario file.
Note: `metrics.py` and `run_scenario.py` do not yet implement quorum, revote, the "definitely no" limit and split consent; add them when coding the logic.

The report includes: metrics per round, final options, credit events, how often the AI's estimates matched real votes, constraint violations and privacy leaks.
